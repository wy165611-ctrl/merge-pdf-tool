# 合并 PDF（macOS）

一个基于 SwiftUI + PDFKit 的本地 PDF 合并桌面应用。无需第三方依赖，文件始终在本机处理。

## 构建

需要 macOS、Swift 5+ 兼容的 `swiftc`，以及系统自带的 SwiftUI、AppKit、PDFKit、UniformTypeIdentifiers 框架。当前脚本不依赖完整 Xcode，可在只有 Command Line Tools 的环境中构建：

```bash
./build.sh
```

产物位于：`build/合并 PDF.app`。可双击打开，也可以运行：

```bash
open "build/合并 PDF.app"
```

## 使用

1. 将多个 PDF 拖入窗口，或点击“添加 PDF”。列表顺序就是默认合并顺序。
2. 点击“添加文件夹”可读取所选文件夹中的所有直接子文件；其中的 PDF 会按文件名自然排序加入列表，非 PDF 会提示并跳过。
3. 点击“粘贴顺序”，可以粘贴自然语言，例如“按照申请表、教务处、竞赛证书合并”，应用会忽略文件名中的下划线、空格、标点和数字后缀，按关键词出现顺序匹配文件；也支持每行一个文件名、完整路径、数字序号以及省略 `.pdf` 扩展名。粘贴内容中没有提到的文件会从当前列表移除，但不会删除磁盘上的原文件。
4. 直接拖动列表项目调整顺序；单项可点垃圾桶删除，也可以点击“清空”。
5. 点击“合并 PDF”，选择保存位置。上次保存目录会自动记住。
6. 合并成功后可点击“在 Finder 中显示”。

非 PDF、损坏/不可读、加密/需要密码、空文件会在添加时给出中文提示；保存失败会在合并完成阶段提示。应用不会主动压缩页面，使用 PDFKit 逐页写入并保留页面尺寸与方向。

## 验收测试

运行测试脚本会生成 3 个不同页数/方向的小型 PDF，并使用 PDFKit 合并，验证总页数、页面尺寸和顺序：

```bash
./Tests/run_tests.sh
```

测试脚本也会验证一个非 PDF 文件被拒绝，以及一个空列表不会生成输出。

## 已知限制

- 首版面向 macOS；需要 macOS 13 或更高版本。
- 同名目标文件如果已有，会在用户明确点选保存并确认后由系统保存面板处理；合并代码只在拿到目标路径后覆盖已有目标。
- 不支持为加密 PDF 自动提供密码；这类文件会被拒绝并提示用户。
